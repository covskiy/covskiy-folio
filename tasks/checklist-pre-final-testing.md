# Чек-лист предфинального тестирования — задачи 02 + 03

Дата подготовки: 2026-11-08, актуализирован после задачи 03 (пакет надёжности
и пакет «контракт знаний», коммиты `aad6b20`…`c03dcee`). Ветка:
`refactor/bot-architecture`. Всё поведение и справка **запекаются в деплой** —
тестируй деплой, собранный после коммита `c03dcee`.

Что изменилось с прошлой версии чек-листа (задача 02) и потому проверяется
отдельно: верхний try/catch роутера, безопасное чтение справки (`answer()` не
бросает, UI-ветки деградируют), контракт записей справки (`id`/`chip`/`about`),
кнопки Telegram с `callback_data = "ask:{id}"` вместо индекса, строго один
плейсхолдер `{{KNOWLEDGE}}`.

## Где тестировать

- **Вебчат**: preview-деплой ветки на Vercel (или локально `npm run dev` + `npm run dev:function`).
- **Telegram @botCovskiy**: вебхук смотрит на прод → Telegram-сценарии либо на проде
  после мержа, либо переключив вебхук через `/api/telegram-setup` (осторожно: прод
  на это время замолчит). Проще: Telegram-блок пройти после мержа в main.
- **Диагностика**: `GET /api/telegram-setup?section=health` с секрет-заголовком —
  LLM / Redis / Telegram одним ответом.

## A. Telegram — справка и правила (после мержа или на переключённом вебхуке)

1. `/start` → приветствие + ровно 3 кнопки: **«Услуги», «Стоимость», «Контакты»**.
   Состав кнопок теперь задают пометки `chip: true` в `knowledge.json`, а не
   порядок массива — на кнопках это не видно, но состав обязан совпасть с чипсами
   вебчата (см. C1).
2. Кнопка → спиннер гасится сразу → «печатает…» (окно ~5 с; при ответе дольше 5 с
   индикатор исчезает сам — это норма, повторов не делаем) → ответ. Старая
   клавиатура снята (editMessageText без кнопок).
3. «Стоимость» → **без цифр**, «оценка под задачу», предложение обсудить лично.
4. «Контакты» → @devCovskiy, почта, GMT+5; **телефона нет и быть не должно**.
5. Свободный текст «делаешь PWA?» → ответ про PWA.
6. «Сколько стоит сайт?» → без цифр, «оценка под задачу», личные контакты.
7. «Дай телефон» → **не выдумывает номер**, ведёт в Telegram/почту.
8. Офф-топик («кто выиграет финал?») → вежливо: бот-визитка разработчика, возврат к теме.
9. Непокрытый вопрос → честно «нет в справке» + @devCovskiy / почта.
10. «Как связаться?» → контакты прямо в чате.
11. `/about` → начинается с «Константин Ковский…» (не «Меня зовут Covskiy»).
    Привязка теперь по пометке `about: true`: заголовок «Кто я» можно переименовывать
    без поломки команды — на проде переименовывать не надо, это покрыто тестами.
12. **Старые кнопки** (в сообщении `/start`, отправленном ботом **до** этого деплоя,
    они несут индекс `ask:0…2`) → нажатие даёт всплывашку **«Кнопка устарела.
    Набери /start — дам свежие подсказки»**, спиннер гаснет, LLM не вызывается,
    чужой ответ не приходит. Если старого сообщения в чате нет — нажми `/start`
    до пуша и сохрани его для этого шага.
13. `/help`, `/reset`; после `/reset` переспроси то же — ответ без прошлого контекста.
14. Стиль всех ответов: от первого лица, коротко, **без markdown** (никаких `**`, `##`, таблиц).

## B. Дедупликация (эмуляция — руками из Telegram не вызвать)

Двойной POST того же апдейта curl'ом (эмуляция ретрая Telegram):

- второй ответ → 200, **без второго сообщения** и без вызова LLM;
- в Redis появился ключ `tg:seen:{update_id}` (TTL 1 ч).
  Повтор после сбоя отправки доходит до LLM — покрыто тестами, руками опционально.

## C. Вебчат

1. Чипы = Услуги / Стоимость / Контакты (пометки `chip`); клик отправляет
   заголовок как вопрос.
2. Диалог с контекстом («а подробнее?» → держит тему); «новый диалог» → сброс.
3. Бейдж «офлайн-справка» появляется, если LLM недоступен.
4. Стены: 16+ вопросов за час с одного IP → 429 «слишком много запросов».
5. Любое непредвиденное исключение API (если вдруг поймаешь 500) — JSON-тело
   `{ok:false, error:"Internal Error"}`, а не HTML-заглушка платформы.

## D. Dumb-режим (опционально, локально)

`npm run dev:function` с `.env.local`, где `LLM_BASE_URL` затёрт (или мусорный),
затем curl вопросов на `127.0.0.1:3000/api/telegram` с секрет-заголовком:

- «как связаться?» → entry «Контакты» (слово «связаться» в тексте — попадание);
- «что такое PWA?» → услуга PWA;
- «работаете с чужим кодом?» → FAQ-пара.
  Известная особенность (не баг): dumb ищет точные слова — «сколько стоит?» может
  дать fallback, т.к. в entry «Стоимость» слова «стоит» нет.

## E. Деградация справки (опционально, локально — проверка пакета надёжности)

Локально: временно переименуй `bot/brain/knowledge.json` (например, в
`knowledge.json.bak`), перезапусти `npm run dev:function`, затем:

1. `GET /api/chat` → **200** `{"ok":true,"service":"webchat","chips":[]}` — не 500;
2. `POST` вопроса → **200** `{"text":"Справка временно недоступна. 🛠…","mode":"dumb"}` —
   не 500, LLM не зовётся;
3. в логе адаптера — ровно один `[knowledge] справка недоступна: …` (исход чтения
   кэшируется, повторных warn на каждый запрос нет);
4. верни файл обратно, перезапусти адаптер — чипсы и обычные ответы вернулись.

Это же на проде делать не нужно: смоук-тесты реального справки и промта в
pre-commit ловят битую правку контента до коммита.

## F. Логи (Vercel → Observability)

- Нет нового шума: warn — только деградации; префиксы `[brain]`, `[store]`,
  `[rate-limit]`, `[knowledge]` (последний — только при битой/недоступной справке).
- Rate-limit warn один ключ на модуль (`exceeded`), а не россыпь по IP.
- Пропуски дедупликации — на `debug`, с дефолтным `LOG_LEVEL=warn` на проде не видны.
- Если поймал `[brain] … {{KNOWLEDGE}} …` — промт-файл правили мимо контракта
  (плейсхолдер обязан быть ровно один); в чате при этом работает dumb-режим.

## G. Если что-то не так

- Симптом → файл: поток Telegram — `bot/http/telegram-webhook.ts` (кнопки —
  `startKeyboard`/`handleCallbackQuery`, формат `ask:{id}`); глупые/неверные
  ответы — `bot/brain/knowledge.json` и `prompts/*.md` (правятся без кода,
  контракт полей — `docs/manual.md` §5.1); состав чипсов/кнопок — пометки `chip`
  в том же JSON; недоступность справки — `bot/brain/knowledge.ts` (`load`) и
  логи `[knowledge]`; недоступность — health-роут + логи.
- Возвращайся в ZCode с симптомами: контекст — `tasks/03-chat-audit-findings.md`
  (пакеты 1–2 реализованы, коммиты в истории ветки).
