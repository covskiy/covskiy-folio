## Контекст: что сейчас не так

Dumb-режим живёт внутри `bot/brain/brain.ts`: `tokenize()`, `STOP_WORDS`,
`dumbAnswer()`, `DUMB_SCORE_THRESHOLD = 0.2`. Это одновременно и алгоритм, и
оркестрация, и пользовательские тексты.

На реальной справке:

- **«Сколько стоит?» → fallback.** В `knowledge.json` нет слов «сколько» и
  «стоит», а «Стоимость» не содержит подстроку «стоит» (`includes("стоит")` не
  срабатывает).
- **«Сколько стоит PWA?» → описание PWA без цены.** Совпало только `pwa`;
  `сколько`/`стоит` — нет.
- **«телеграм» кириллицей не находит `Telegram` латиницей** — разные алфавиты.
- **Ответ без заголовка:** «Пять направлений:…» — непонятно, о чём это.
- **Длинные записи выигрывают случайно:** больше текста — больше шансов
  зацепить слово вопроса; редкие термины (`NDA`, `PWA`) и частые (`сайт`, `бот`)
  весят одинаково.
- **`length >= 3` отбрасывает `IT`, `UX`, `AI`, `ИИ`.**
- **Индекс пересобирается на каждый fallback:** все записи заново
  токенизируются.
- **Пользователь не видит, что спросить дальше.** Чипсы есть только при старте
  вебчата и исчезают после первого вопроса; в Telegram кнопки есть только в
  `/start`. В dumb-fallback это особенно обидно: человек попал в офлайн-режим и
  остался с «Не нашёл».
- **Ошибка сборки промта маскируется под отказ LLM.** `systemPrompt(entries)`
  вызывается внутри `try` вокруг `llm.chat()`, поэтому сломанный
  `{{KNOWLEDGE}}` логируется как `LLM недоступен (...)`.
- **`/help` в Telegram есть, но он статичный и не подсказывает темы.** В вебчате
  команды помощи нет вообще — только приветствие и стартовые чипсы.

## 1. Вынос dumb-поиска

### Куда выносить

Новый модуль: **`bot/brain/search.ts`**, рядом с `knowledge.ts` и `prompt.ts`.

Не `bot/dumb.ts` и не `bot/search.ts` в корне: `bot/llm.ts` — это транспорт
(сеть, env, таймауты), а dumb-поиск — доменная логика над `KnowledgeItem`.
Симметрия с `llm.ts` должна быть не в расположении файла, а в `BrainDeps`:
`llm` и `search` — две инъекции, `brain.ts` — оркестратор.

### API

```ts
// bot/brain/search.ts
export interface SearchHit {
  item: KnowledgeItem;
  score: number;
}

/**
 * Ранжирует записи справки под вопрос. Возвращает все ненулевые попадания
 * по убыванию score; пусто — ни одно слово не совпало.
 *
 * Порог уверенности применяет brain: попадания ниже порога нужны для
 * подсказок «возможно, ты искал это».
 */
export function rankKnowledge(question: string, entries: readonly KnowledgeItem[]): SearchHit[];
```

Почему возвращаются **все** попадания, а не только прошедшие порог:

- подсказки в dumb-режиме логично строить из ближайших тем ниже порога;
- порог — это политика ответа, а не алгоритм ранжирования;
- тесты поиска проверяют порядок, тесты brain — что считать уверенным ответом.

`brain.ts`:

```ts
const DUMB_SCORE_THRESHOLD = 0.3;
const DUMB_SUGGESTIONS_LIMIT = 3;

const hits = search(question, entries);
const best = hits[0];

if (best && best.score >= DUMB_SCORE_THRESHOLD) {
  return { text: formatHit(best), mode: "dumb" };
}

const suggestions = pickSuggestions(hits, entries, knowledge);
return {
  text: suggestions.length > 0 ? FALLBACK_WITH_SUGGESTIONS : FALLBACK_PLAIN,
  mode: "dumb",
  ...(suggestions.length > 0 ? { suggestions } : {}),
};
```

`formatHit()` форматирует `title + text`:

```ts
`${item.title}\n\n${item.text}`;
```

Telegram и вебчат работают с plain text (`parse_mode` не задан, виджет
использует `textContent`), поэтому markdown не нужен.

`BrainDeps` получает:

```ts
search?: typeof rankKnowledge;
prompt?: typeof systemPrompt; // нужно для теста честного лога, см. §5
```

`FALLBACK_WITH_SUGGESTIONS`, `FALLBACK_PLAIN` и `UNAVAILABLE_ANSWER` остаются
в `brain.ts`: это пользовательские тексты, а не алгоритм поиска.

### Инварианты модуля

- Не читает файлы, не ходит в сеть, не логирует.
- Никогда не бросает: пустой вопрос, пустая справка, пунктуация → `[]`.
- Детерминирован: одинаковый вход → одинаковый порядок.
- Кэш индекса — `WeakMap<readonly KnowledgeItem[], Index>` по идентичности
  массива, как `promptCache` в `prompt.ts`. `knowledge.load()` возвращает
  стабильный массив, поэтому индекс собирается один раз на инстанс функции.

## 2. Качество поиска

### Нормализация

1. `lowercase`, `ё → е`.
2. Разбиение по `\p{L}\p{N}` с флагом `u`; дефис — разделитель
   (`PWA-приложения` → `pwa`, `приложения`).
3. Расширенные стоп-слова: `сколько`, `расскажи`, `расскажите`, `подскажи`,
   `плиз`, `не`, `на`, `по`, `из`, `от`, `до`, `вы`, `мы`, `ты`, `тобой` и т.п.
4. Короткие технические слова — отдельный allowlist: `IT`, `UX`, `UI`, `AI`,
   `ИИ`, `JS`, `TS`. Не снижать общий минимум длины: иначе в индекс полезет шум.

### Морфология

Лёгкий стемминг без словарей:

- отсечение частых русских окончаний (`ами`, `ями`, `ого`, `его`, `ыми`,
  `ими`, `ах`, `ях`, `ам`, `ям`, `ов`, `ев`, `ой`, `ый`, `ий`, `ая`, `яя`,
  `ое`, `ее`, `ые`, `ие`, `ую`, `юю`, `ом`, `ем`, `ы`, `и`, `а`, `я`, `о`,
  `е`, `у`, `ю`, `ь`);
- сравнение по основе или по первым 4 символам при длине ≥ 4.

Примеры:

| Вопрос      | В справке   | Совпадение              |
| ----------- | ----------- | ----------------------- |
| `стоит`     | `Стоимость` | `стои` = `стои`         |
| `цены`      | `цена`      | `цен` = `цен`           |
| `нейросети` | `нейросеть` | `нейросет` = `нейросет` |
| `сайты`     | `сайт`      | `сайт` = `сайт`         |

Стемминг эвристический: финальные правила проверяются корпусом вопросов, а не
«на глаз».

### Скоринг

Индекс записи:

- `title` — вес `1.0`;
- `keywords` — вес `1.0` (курируемые синонимы);
- `text` — вес `0.5`.

`idf(term) = log(1 + N / max(df(term), 1))`, где `N` — число записей, `df` —
в скольких записях термин встречается. Score:

```text
sum(idf(term) * fieldWeight) / sum(idf(term) по всем словам вопроса)
```

Стартовый порог — `0.3`; финальные веса и порог подбираются корпусом.

Tie-break: score → число сильных совпадений (`title`/`keywords`) → порядок в
файле.

Что это исправляет:

- «Сколько стоит?»: `сколько` — стоп-слово, `стоит` → основа `стои` →
  заголовок «Стоимость» → уверенный ответ;
- «Сколько стоит PWA?»: редкое `стоит` весит больше частого `pwa`, первым идёт
  «Стоимость», а не описание PWA;
- «Сколько стоит PWA?» остаётся top-1: «Стоимость». Multi-hit (обе записи в
  одном ответе) — вне этой задачи (P2): публичный контракт не меняется;
- длинные записи больше не выигрывают только за счёт объёма: вклад даёт
  совпадение конкретного слова, а редкие слова весят больше.

## 3. `keywords` в `knowledge.json`

Расширить контракт:

```ts
export interface KnowledgeItem {
  id: string;
  title: string;
  text: string;
  /** Синонимы для dumb-поиска; в промт и UI не попадают. */
  keywords?: string[];
  /** Запись-контакт: гарантированная подсказка в dumb-fallback. */
  contact?: true;
  chip?: true;
  about?: true;
}
```

Валидация в `knowledge.ts` — fail-soft, как у `chip`/`about`:

- `keywords` нет → поле отсутствует, всё работает;
- `keywords` — массив непустых строк → сохраняется;
- строка/число/массив с пустой строкой → `warn`, поле удаляется, запись
  остаётся;
- `contact` не `true` → `warn`, флаг игнорируется, запись остаётся;
- если `contact: true` стоит у нескольких записей — используется первая в файле,
  это не ошибка.

`keywords` **не** попадают в `systemPrompt()` и `uiTopics()`: это только
поисковый слой.

Стартовый набор (ключевые записи):

```json
{
  "id": "pricing",
  "title": "Стоимость",
  "keywords": [
    "цена",
    "цены",
    "стоимость",
    "стоит",
    "бюджет",
    "дорого",
    "оплата",
    "ставка",
    "смета"
  ]
}
```

```json
{
  "id": "contacts",
  "title": "Контакты",
  "contact": true,
  "keywords": [
    "связаться",
    "написать",
    "контакт",
    "контакты",
    "почта",
    "email",
    "телеграм",
    "telegram",
    "тг",
    "позвонить"
  ]
}
```

Остальные по мере необходимости:

- `services`: `услуги`, `направления`, `умеешь`, `делаешь`, `чем занимаешься`,
  `навыки`, `помощь`;
- `about`: `кто ты`, `о себе`, `биография`, `кто я`;
- `nda`: `nda`, `соглашение`, `конфиденциальность`;
- `legacy-code`: `чужой код`, `легаси`, `рефакторинг`, `аудит`, `миграция`;
- `non-tech-clients`: `не разбираюсь`, `без технических знаний`, `простым
  языком`, `бизнес`;
- `cooperation`: `сотрудничество`, `формат работы`, `проект с нуля`,
  `как работаем`;
- `service-pwa`: `pwa`, `прогрессивное веб-приложение`, `установка на телефон`,
  `офлайн`;
- `service-telegram-bots`: `телеграм`, `telegram`, `бот`, `mini app`,
  `мессенджер`;
- `service-ai`: `нейросети`, `ии`, `llm`, `чат-бот`, `автоматизация`.

Правило для владельца: `keywords` — это слова, которыми люди называют тему, а
не пересказ текста. Если вопрос стабильно не находится, сначала добавляем
синоним в `keywords`, а не правим алгоритм.

**Не добавлять в `keywords` стоп-слова** (`сколько`, `как`, `что`, `где`,
`расскажи`, `подскажи` и т.п.): они вырезаются и из запроса, и из `keywords`,
поэтому такой синоним не сработает. В частности, `сколько` — стоп-слово, а не
keyword: «Сколько стоит?» ловится через `стоит`/`цена`/`стоимость`, а не через
`сколько`.

## 5. Честный лог ошибки сборки промта

Сейчас в `brain.ts`:

```ts
try {
  return {
    text: await llm.chat([
      { role: "system", content: systemPrompt(entries) },
      ...
    ]),
    mode: "llm",
  };
} catch (error) {
  log.error("brain", `LLM недоступен (${reason}), отвечаю в dumb-режиме`);
}
```

Если `systemPrompt()` бросил из-за сломанного `{{KNOWLEDGE}}`, в лог уходит
«LLM недоступен», хотя LLM не вызывался. Это врёт про причину и мешает
диагностике.

Исправить:

1. Собрать промт **до** `try` вокруг `llm.chat()`:

   ```ts
   let prompt: string;
   try {
     prompt = promptFn(entries);
   } catch (error) {
     log.error("brain", `system-промт не собран (${reason}), отвечаю в dumb-режиме`);
     return dumbAnswer(question, entries);
   }

   try {
     const text = await llm.chat([{ role: "system", content: prompt }, ...recent, question]);
     return { text, mode: "llm" };
   } catch (error) {
     log.error("brain", `LLM недоступен (${reason}), отвечаю в dumb-режиме`);
     return dumbAnswer(question, entries);
   }
   ```

2. Добавить `BrainDeps.prompt?: typeof systemPrompt`, чтобы тест мог подменить
   сборщик и проверить лог без правки реальных md.

3. Тест: `prompt` бросает → `llm.chat` не вызван; `log.error` содержит
   `system-промт не собран`; в логе нет `LLM недоступен`; ответ `mode: "dumb"`;
   `answer()` не бросает.

Не входит в эту задачу: типизированная ошибка «LLM не настроен» и throttling
лога для штатного режима без `LLM_*`. Это отдельное улучшение наблюдаемости.

## 6. Offline-справка и команда помощи

### Принцип

Помощь — это интерфейсная команда, а не знание. Она не должна зависеть от LLM,
Redis и `knowledge.json` (кроме списка тем для кнопок). В dumb-режиме она
объясняет, что бот продолжает работать по справке, и даёт кликабельные темы.

### Общий текст

Новый модуль **`bot/brain/help.ts`**:

```ts
export const HELP_TEXT_WEBCHAT = [
  "Я — справка этого сайта. Отвечаю на вопросы об услугах, опыте, стоимости, форматах работы и контактах.",
  "Если нейросеть недоступна, работаю по той же справке — это штатный офлайн-режим, а не ошибка.",
  "Нажми тему ниже или задай вопрос иначе.",
].join("\n");

export const HELP_TEXT_TELEGRAM = [
  "Что я умею:",
  "• отвечаю на вопросы по справке сайта — об услугах, опыте, стоимости и контактах;",
  "• работаю и без нейросети — по той же справке;",
  "• /about — коротко о владельце;",
  "• /reset — начать новый диалог;",
  "• /help — этот список.",
].join("\n");

export const HELP_TEXT_WEBCHAT_FALLBACK =
  "Я — справка сайта. Спроси об услугах, стоимости или контактах.";
```

Почему два основных текста: в вебчате нет `/about` и `/reset`, а в Telegram нет
чипсов. `HELP_TEXT_WEBCHAT_FALLBACK` — только страховка, если `GET /api/chat` не
ответил; это не второй источник бизнес-логики.

### Вебчат

- В шапке виджета три кнопки: `?` (помощь), `⟳` (новый диалог), `✕` (закрыть).
- `GET /api/chat` возвращает `help` **всегда**, даже если `knowledge.json`
  недоступен: это статический текст. Форма ответа:

```json
{
  "ok": true,
  "service": "webchat",
  "chips": [{ "title": "Услуги" }],
  "help": "Я — справка этого сайта…"
}
```

- `src/chat/chat-api.ts`: `fetchChips()` заменяется на
  `fetchChatBootstrap(): Promise<{ chips: ChatChip[]; help: string }>`.
  Ошибка сети или не-2xx → `{ chips: [], help: "" }`.
- Бутстрап грузится один раз; повторные клики по `?` не делают новый запрос.
- Клик по `?`:
  1. если бутстрап ещё не загружен — дождаться его;
  2. убрать старые подсказки/чипсы;
  3. добавить сообщение ассистента с `help` или
     `HELP_TEXT_WEBCHAT_FALLBACK`;
  4. показать чипсы из бутстрапа, если они есть.
     В `POST /api/chat` клик по `?` не ходит.
- Ввод `/help` или `/start` — только exact-match после `trim()` и
  `toLowerCase()`; `/help extra` считается обычным вопросом.
  - команда показывается как сообщение пользователя, затем ответ ассистента;
  - `/help` → текст помощи + чипсы;
  - `/start` → существующий `GREETING` из `chat-widget.ts` + чипсы;
  - в `POST /api/chat` и историю Redis команда не уходит.
- Клик по чипу или подсказке — обычный `sendMessage(title)`, уходит в
  `POST /api/chat` и пишется в историю.
- При новом вопросе старые подсказки удаляются.
- `suggestions` в ответе API — только `{ title }`, без `id`:

```json
{
  "ok": true,
  "text": "Не нашёл точного ответа…",
  "mode": "dumb",
  "suggestions": [{ "title": "Контакты" }]
}
```

Если подсказок нет — поля `suggestions` в JSON нет.

### Telegram

- Перенести `HELP_TEXT` из `telegram-webhook.ts` в `help.ts`
  (`HELP_TEXT_TELEGRAM`), чтобы вебчат и Telegram не разъезжались.
- `/help` отправляет `HELP_TEXT_TELEGRAM` + `startKeyboard()`: темы становятся
  кликабельными, помощь работает без LLM. Если `uiTopics()` пуст или справка
  недоступна — только текст.
- `/start` не меняется: `WELCOME_TEXT` + `startKeyboard()`. Строку про offline
  в приветствие не добавляем.
- `/about`, `/reset`, `/start`, `/help` не зовут LLM, не пишутся в историю и не
  тратят лимит вопросов.

## 7. Подсказки в dumb-режиме

### Контракт ответа

Расширить `BrainAnswer`:

```ts
export interface BrainSuggestion {
  id: string;
  title: string;
}

export interface BrainAnswer {
  text: string;
  mode: "llm" | "dumb";
  /** Варианты следующего вопроса; только для dumb-fallback. */
  suggestions?: BrainSuggestion[];
}
```

Правила:

- подсказки появляются **только когда dumb-ответ — fallback**: `hits.length === 0`
  или `hits[0].score < DUMB_SCORE_THRESHOLD`;
- максимум 3;
- near-miss — до 2 лучших попаданий ниже порога;
- затем запись с `contact: true`, если она ещё не попала в список;
- затем `uiTopics(knowledge, DUMB_SUGGESTIONS_LIMIT)` добивает список до 3;
- порядок: near-miss → contact → uiTopics;
- дубликаты по `id` убираются;
- `id` нужен Telegram для `callback_data = ask:{id}`, `title` — вебчату и
  Telegram-кнопке;
- при `UNAVAILABLE_ANSWER` подсказок нет: справка недоступна;
- при уверенном dumb-ответе подсказок нет — ответ уже найден.

```ts
const DUMB_SCORE_THRESHOLD = 0.3;
const DUMB_SUGGESTIONS_LIMIT = 3;

function pickSuggestions(
  hits: SearchHit[],
  entries: KnowledgeItem[],
  knowledge: KnowledgeStore,
): BrainSuggestion[] {
  const near = hits
    .filter((hit) => hit.score < DUMB_SCORE_THRESHOLD)
    .slice(0, 2)
    .map((hit) => hit.item);

  const contact = entries.find((item) => item.contact === true);
  const pool = [
    ...near,
    ...(contact ? [contact] : []),
    ...uiTopics(knowledge, DUMB_SUGGESTIONS_LIMIT),
  ];

  const seen = new Set<string>();
  const unique: KnowledgeItem[] = [];
  for (const item of pool) {
    if (seen.has(item.id)) continue;
    seen.add(item.id);
    unique.push(item);
  }

  return unique.slice(0, DUMB_SUGGESTIONS_LIMIT).map(({ id, title }) => ({ id, title }));
}
```

Почему не показывать подсказки после каждого dumb-ответа: это удлиняет UI и
отвлекает от уже полученного ответа. Такое поведение — вне этой задачи.

### Вебчат

- `handleWebChat` возвращает `{ ok: true, text, mode, suggestions? }`, где
  `suggestions` — `{ title }[]` (id клиенту не нужен); если подсказок нет,
  поле отсутствует.
- `chat-api.ts`: `askChat()` возвращает `suggestions?: ChatChip[]`; валидация
  как у чипсов, максимум 3.
- `chat-widget.ts`: после dumb-fallback рисует ряд чипов под ответом
  (переиспользовать `.chat__chips` / `.chat__chip`), клик отправляет `title`
  как обычный вопрос. На новый вопрос старые подсказки удаляются.
- Не использовать `innerHTML` с данными; только `textContent`.

### Telegram

- `answerAsQuestion()` получает `{ text, mode, suggestions }`.
- Если `suggestions.length > 0` — собрать `TgInlineKeyboardMarkup` с
  `{ text: title, callback_data: "ask:" + id }` и передать в `sendMessage`
  третьим аргументом.
- Клик идёт в существующий `handleCallbackQuery`: находит запись по `id` и
  задаёт её `title` как обычный вопрос. Ничего нового в callback-протоколе не
  нужно.
- Если `suggestions` нет — отправить текст без клавиатуры (как сейчас).
- При уверенном dumb-ответе и LLM-ответе клавиатуры нет. Старые клавиатуры на
  предыдущих сообщениях не чистим: это штатное поведение Telegram, как у
  `/start`.

### Тексты fallback

Два варианта, выбор по наличию подсказок:

```ts
const FALLBACK_WITH_SUGGESTIONS = [
  "Не нашёл точного ответа в справке. 🤔",
  "Попробуй спросить иначе или выбери тему ниже.",
].join("\n");

const FALLBACK_PLAIN = ["Не нашёл точного ответа в справке. 🤔", "Попробуй спросить иначе."].join(
  "\n",
);
```

- `FALLBACK_WITH_SUGGESTIONS` — если `suggestions.length > 0`;
- `FALLBACK_PLAIN` — если подсказок нет;
- `UNAVAILABLE_ANSWER` не меняем: это отдельный fail-safe, не fallback поиска.

Так «страница Контакты» уходит из текста, а контакты всё равно доступны
кнопкой/чипом благодаря записи с `contact: true`.

## 10. Критерии готовности

- `npm run test`, `npm run typecheck`, `npm run lint`, `npm run format:check`
  зелёные.
- LLM-путь, `UNAVAILABLE_ANSWER`, `HISTORY_WINDOW`, формат ответа API и
  `mode` не изменились.
- Dumb-режим не ходит в сеть, не бросает, детерминирован.
- С пустыми `LLM_BASE_URL`/`LLM_MODEL`:
  - «Сколько стоит?» → «Стоимость» с заголовком и текстом;
  - «Сколько стоит PWA?» → «Стоимость» первым;
  - «телеграм» → «Контакты» / «Услуги: Telegram-боты»;
  - «ракета на марс» → `FALLBACK_WITH_SUGGESTIONS` + до 3 подсказок; среди них
    есть «Контакты», если у записи стоит `contact: true`;
  - уверенный dumb-ответ → без подсказок;
  - клик по подсказке в вебчате отправляет вопрос и получает ответ;
  - клик по подсказке в Telegram приходит в `handleCallbackQuery` и отвечает.
- `/help` в Telegram работает без LLM и показывает темы кнопками; при
  недоступной справке — только текст.
- В вебчате работают и `?`, и `/help`, и `/start` — без похода в LLM; `?` и
  команды не пишутся в историю.
- `GET /api/chat` отдаёт `help` даже при недоступной справке; `POST /api/chat`
  не отдаёт `suggestions`, если подсказок нет.
- Сломанный `{{KNOWLEDGE}}` логируется как `system-промт не собран`, а не
  `LLM недоступен`; `llm.chat` при этом не вызывается.
- Публичный API обратно совместим: старые клиенты игнорируют новые
  `suggestions`/`help`.
- `keywords` не попадают в промт и UI; `contact` не влияет на чипсы.

## 11. Инварианты

1. Один «мозг» на вебчат и Telegram; различия — только в адаптерах.
2. Относительные импорты в `bot/` — только с `.js`.
3. Dumb-режим не вызывает LLM, `fetch`, Redis и не читает файлы сам: справку
   передаёт brain.
4. `mode: "llm" | "dumb"` — публичный контракт, не меняем.
5. Подсказки и помощь не ходят в историю диалога и не тратят лимит вопросов.
   Нажатие на подсказку/чип — обычный вопрос: история и лимит применяются как
   раньше.
6. Подсказки появляются **только** в dumb-fallback. LLM-ответ, уверенный
   dumb-ответ и `UNAVAILABLE_ANSWER` подсказок не содержат.
7. `keywords` — только поисковый слой: не в промт, не в UI, не в чипсы.
8. `contact: true` влияет только на подсказки fallback: не в промт, не в
   `uiTopics`, не в чипсы.
9. `rankKnowledge()` не знает про порог: он возвращает все попадания со
   `score > 0`, порог и лимит подсказок живут в `brain.ts`.
10. Тесты не ходят в сеть.
11. `knowledge.json` остаётся единственным местом правки контента; `help.ts` —
    единственным местом текста помощи.

## 12. Принятые решения

Открытых вопросов нет: по каждому пункту выбрано одно поведение.

| Вопрос                                             | Решение                                                                                                      |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Когда показывать подсказки?                        | Только в dumb-fallback (`hits` пуст или `hits[0].score < 0.3`).                                              |
| Вебчат: кнопка `?` или команда `/help`?            | И то, и другое: кнопка `?` + локальный перехват `/help` и `/start`; в `POST` и историю не ходят.             |
| Telegram `/help`: текст или кнопки?                | `HELP_TEXT_TELEGRAM` + `startKeyboard()`; при недоступной справке — только текст.                            |
| Источник подсказок?                                | До 2 near-miss → запись с `contact: true` → `uiTopics`; дедупликация по `id`, максимум 3.                    |
| Multi-hit в одном dumb-ответе?                     | Нет, только top-1. Отдельная задача после P0.                                                                |
| «Страница Контакты» в fallback?                    | Убираем: `FALLBACK_PLAIN` / `FALLBACK_WITH_SUGGESTIONS`; контакт гарантируется подсказкой `contact: true`.   |
| Текст помощи: один или два?                        | Два: `HELP_TEXT_WEBCHAT` и `HELP_TEXT_TELEGRAM`; плюс `HELP_TEXT_WEBCHAT_FALLBACK` на случай сетевой ошибки. |
| Куда выносить dumb-поиск?                          | `bot/brain/search.ts`, порог — в `brain.ts`.                                                                 |
| Что считается контактом?                           | Явный флаг `contact: true` у записи, а не совпадение по `id`.                                                |
| `сколько` — стоп-слово или keyword?                | Стоп-слово; в `keywords` цена ловится через `цена`/`стоит`/`стоимость`/…                                     |
| Как ведут себя `keywords` и `contact` в промте/UI? | Никак: `keywords` — только поиск, `contact` — только подсказки fallback.                                     |

Всё, что осталось настраиваемым, — это **контент**, а не логика:

- тексты помощи в `bot/brain/help.ts`;
- синонимы в `keywords` и флаг `contact` в `bot/brain/knowledge.json`.

Их правка не требует изменения кода и не является открытым вопросом ТЗ.
