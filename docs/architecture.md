# Архитектура

## Общая схема

```
Браузер (статика: Vite MPA, dist/)                    Telegram
   │  POST /api/chat {messages}                          │  POST /api/telegram (update)
   ▼                                                     ▼
        ┌──────────────── vercel.json (rewrites) ────────────────┐
        │            /api/chat  ─┐            /api/telegram ─┐   │
        └────────────────────────┼───────────────────────────┼───┘
                                 ▼                           ▼
                     ┌───────────────────────────────────────────┐
                     │        api/bot.ts — ОДНА функция          │
                     │        роутер по pathname                 │
                     └──────────────┬────────────────────────────┘
                                    ▼
                     lib/webchat.ts        lib/telegram-webhook.ts
                             └──────┬──────┘
                                    ▼
                            lib/brain.ts — answer()
                        LLM (OpenAI-совместимый API)
                                   ↘ при ошибке/таймауте
                            dumb-поиск по lib/knowledge.ts
```

## Почему одна функция, а не две

Файлы в корневом `api/` Vercel деплоит как отдельные функции. Свежая рекомендация
документации Vercel: держать связанные маршруты в **одной общей функции** — тогда
Fluid compute переиспользует один инстанс для обоих источников (меньше холодных
стартов), в дашборде один объект, и общий код `brain` грузится один раз.

Чтобы URL остались семантичными (`/api/chat`, `/api/telegram`), в `vercel.json`
настроены два rewrites на `/api/bot`. Это единственный `vercel.json` в проекте —
Vite детектится и собирается сам (`vite build` → `dist/`).

Сигнатура функции — современный Web-стандарт (рекомендация Vercel):

```ts
export default {
  async fetch(request: Request): Promise<Response> { … }
};
```

## «Мозг» — lib/brain.ts

`answer(history)` — единая точка входа для вебчата и Telegram:

1. **LLM-ветка.** Читает `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`. Запрос — обычный
   `fetch` на `${LLM_BASE_URL}/chat/completions` (OpenAI-совместимый формат: system-промпт
   со справкой из `lib/knowledge.ts` + история диалога). Таймаут — `AbortSignal.timeout(15000)`.
   Endpoint любой: Ollama Cloud (`https://ollama.com/v1`), llama.cpp (`http://127.0.0.1:8080/v1`).
2. **Dumb-ветка (fallback).** Любая ошибка — нет env, endpoint недоступен, таймаут, 5xx,
   пустой ответ — и вопрос обрабатывается детерминированно: текст нормализуется,
   токены (слова ≥ 3 букв без стоп-слов) сравниваются с каждым параграфом справки,
   побеждает лучший по доле совпадений (порог 0.2). Ниже порога — вежливый fallback.

Ответ помечается `mode: 'llm' | 'dumb'` — виджет показывает бейдж «офлайн-справка».

## Вебчат — lib/webchat.ts + src/chat/

- Историю диалога несёт **клиент** (localStorage → последние 12 сообщений в запросе).
  Поэтому проект работает без базы данных; серверная память (Upstash Redis) добавляется
  одной командой, если понадобится контекст на сервере.
- `lib/webchat.ts` валидирует вход: только POST (GET — smoke `{ok:true}`), JSON,
  массив `messages`, роли `user|assistant`, обрезка длины и количества.
- `src/chat/chat-api.ts` — клиент: localStorage, POST последних 8 сообщений.
- `src/chat/chat-widget.ts` — UI: плавающая кнопка, панель, индикатор «печатает…»,
  бейдж dumb-режима. Никакого innerHTML с данными пользователя — только `textContent`.

## Telegram — lib/telegram-webhook.ts + lib/telegram-api.ts

- Webhook принимает только POST с заголовком `X-Telegram-Bot-Api-Secret-Token`,
  равным `TELEGRAM_WEBHOOK_SECRET` (секрет задаётся при setWebhook). Иначе — 401:
  чужие запросы не тратят вызовы LLM.
- `/start` — приветствие; обычный текст — через `answer()`, ответ уходит `sendMessage`
  в тот же чат. Ошибки отправки/LLM ловятся, наружу всегда отдаётся 200 (иначе
  Telegram будет повторять доставку update).
- `lib/telegram-api.ts` — тонкая обёртка Bot API на `fetch`, без зависимостей.

## Безопасность

- Секреты живут только в env (Vercel) и `.env.local` (в `.gitignore`). На фронте
  секретов нет вообще — `/api/chat` публичный по дизайну (это справка).
- Webhook защищён secret-заголовком; без валидного секрета — 401.
- Валидация входа: длины, роли, количество сообщений — защита от мусорных запросов.
- CORS не настраивается: сайт и `/api` на одном домене (same-origin).

## Ограничения и развитие

- Память диалога только на клиенте; Telegram-бот отвечает на каждое сообщение отдельно.
- dumb-режим ищет по словам, без морфологии и синонимов — это осознанный минимум.
- Идеи на будущее: Upstash Redis (серверная история + rate-limit), векторный поиск
  по справке, /api/health с проверкой LLM-endpoint.
